# Отчет по проекту HSE Bank

## Архитектурный обзор

HSE Bank представляет собой консольное приложение для управления персональными финансами, построенное на принципах чистой архитектуры и современных практик проектирования программного обеспечения.

---

## Реализованная функциональность

### Управление банковскими счетами
- Создание новых счетов
- Изменение названий существующих счетов  
- Удаление счетов из системы
- Просмотр полного списка счетов с текущим балансом

### Управление финансовыми категориями
- Добавление новых категорий операций
- Редактирование существующих категорий
- Удаление неиспользуемых категорий
- Просмотр полного списка категорий

### Операционная деятельность
- Регистрация доходных операций
- Учет расходных транзакций
- Связывание операций со счетами и категориями

### Система импорта/экспорта данных
- Импорт финансовых данных из JSON и CSV файлов
- Экспорт данных в JSON и CSV форматы
-   

### Система контроля и аналитики
- Мониторинг производительности операций
- Статистика выполнения пользовательских команд
- Анализ временных метрик

### Механизм управления изменениями
- Отмена последнего выполненного действия
- Восстановление отмененных операций
- Полный контроль над историей изменений

## Принципы проектирования

### SOLID and GRASP Principles

**Single Responsibility Principle → High Cohesion & Creator**  
Каждый компонент системы обладает единственной зоной ответственности, что обеспечивает высокую связность (High Cohesion). Фабрики специализируются на создании объектов (Creator), репозитории обеспечивают доступ к данным, команды и сервисы реализуют бизнес-логику.

**Open/Closed Principle → Protected Variations & Polymorphism**  
Архитектура спроектирована для легкого расширения функциональности через систему интерфейсов, защищая систему от изменений (Protected Variations). Полиморфизм позволяет добавлять новые реализации без модификации существующего кода.

**Liskov Substitution Principle → Polymorphism & Information Expert**  
Наследующие классы полностью реализуют контракты родительских сущностей, обеспечивая корректную работу полиморфных конструкций. Классы, владеющие информацией (Information Expert), гарантированно соблюдают контракты предков.

**Interface Segregation Principle → Low Coupling & High Cohesion**  
Интерфейсы системы логически сегментированы согласно их назначению, уменьшая связанность между компонентами (Low Coupling) и увеличивая их связность (High Cohesion). Каждый интерфейс репозитория определяет минимально необходимый контракт.

**Dependency Inversion Principle → Low Coupling & Indirection**  
Все компоненты приложения зависят от абстракций, а не от конкретных реализаций, что минимизирует связанность (Low Coupling) и вводит уровень посредничества (Indirection). Этот принцип последовательно применен на уровнях меню, фасадов и сервисов.

### Дополнительные GRASP принципы

**Controller**  
Уровень меню выступает в роли контроллера, обрабатывающего пользовательские запросы и координирующего работу системы без прямого доступа к бизнес-логике.

**Pure Fabrication**  
Сервисные классы и фасады представляют собой pure fabrication - искусственные конструкции, введенные для решения технических задач, не относящихся к предметной области.

## Внедрение зависимостей

### Архитектура DI
Система использует инъекцию зависимостей на всех уровнях:

**Уровень команд**
```csharp
public class GetAllBankAccountsCommand : IQueryCommand<IEnumerable<BankAccount>>
{
    private IBankAccountRepository _bankAccountRepository;

    public GetAllBankAccountsCommand(IBankAccountRepository bankAccountRepository)
    {
        _bankAccountRepository = bankAccountRepository;
    }
    
    ...
}
```

**Уровень фасадов**
```csharp
public class BankAccountFacade : IBankAccountFacade
{
    private ILogger<BankAccountFacade> _logger;
    private ICommandFactory _commandFactory;
    private ICommandManager _commandManager;

    public BankAccountFacade(ILogger<BankAccountFacade> logger, ICommandFactory commandFactory, ICommandManager commandManager)
    {
        _logger = logger;
        _commandFactory = commandFactory;
        _commandManager = commandManager;
    }

    ...
}
```

### Конфигурация контейнера
Настройка инъекции зависимостей выполняется в каждом модуле в DependencyInjection.

## Архитектурные паттерны

### Factory Pattern
Локализация процесса создания объектов в специализированном модуле Infrastructure.Factories. Централизованное управление валидацией и инициализацией сущностей.

### Command Pattern
Трансформация пользовательских сценариев в объекты-команды в модуле Infrastructure.Commands. Реализация механизмов отмены и повтора отмененных операций через инкапсуляцию действий.

### Decorator Pattern
Инструментарий измерения производительности в Infrastructure.Commands. Накладное наблюдение за временными характеристиками выполнения операций для целей аналитики.

### Visitor Pattern
Реализация системы экспорта данных в модуле Infrastructure.Export. Позволяет легко добавлять новые форматы данных без изменения существующей структуры классов. Каждый формат (JSON, CSV) представлен отдельным посетителем, который обрабатывает необходимые сущности.

### Template Method Pattern
Организация процесса импорта в специализированном модуле Infrastructure.Import. Определяет общий алгоритм обработки данных, позволяя подклассам переопределять отдельные шаги без изменения структуры алгоритма.

### Facade Pattern
Упрощение сложных операций через единые точки доступа в Application.Facades. Абстрагирование пользователя от внутренней сложности бизнес-процессов.

## Технические особенности

### Модульная структура
- **Infrastructure** - низкоуровневые реализации и технические детали
- **Application** - бизнес-логика и координация workflows
- **Domain** - доменные модели и абстракции
- **UserInterface** - реализации меню и взаимодействия с пользователем

### Расширяемость
- Плагинная архитектура через интерфейсы
- Легкость добавления новых хранилищ данных
- Простота интеграции дополнительной функциональности

## Инструкция по запуску

- Клонировать репозиторий
- Открыть проект в среде разработки
- Установить используемые пакеты NuGet: Spectre.Console, Microsoft.Extensions.DependencyInjection, Microsoft.Extensions.Logging, Microsoft.Extensions.Logging.Console
- Запустить проект

Для проверки работы можно импортировать данные из файла data/import/data.json.
